# Anvil 0.5.0 — Release plan

**Theme:** "Linux, properly" + a sharper identity.
**Current version:** 0.4.0 (versionCode 5). **Target:** 0.5.0 (versionCode 6).
Formatted version: https://claude.ai/artifact/TAimKygFGomGXXpNkHhAVa

## Why this release

The most requested thing so far is fetching Linux ISOs from official sources inside the app (feedback from
Ishan Jarwal on LinkedIn). Windows already works end to end; Linux still means "bring your own ISO". Ventoy needs
a second machine, so this is where Anvil wins.

## Goals

1. **Linux catalog** — pick a distro, Anvil downloads the official ISO from a fast mirror and verifies it.
2. **New logo and brand assets** — cleaner anvil, gradient body, spark, themed-icon support.
3. Fix the **"No drivers were found"** dead end on laptops with Intel RST/VMD storage.

## Scope

### 1. Linux catalog (must have)

| Item | Detail |
|---|---|
| Distros | Ubuntu (Desktop LTS + latest), Linux Mint, Fedora Workstation, Debian (netinst + live) |
| Manifest | Remote JSON manifest (distro, version, arch, mirror list, checksum URL, key id) so releases update without an app update. Bundled fallback copy in assets |
| Mirror choice | Probe candidate mirrors (small ranged GET, latency + throughput), pick fastest, fall back to next on failure |
| Verification | Fetch `SHA256SUMS` (+ `.gpg` / signed `CHECKSUM` for Fedora). Verify the signature with pinned distro keys (Bouncy Castle), then verify the ISO SHA-256 |
| Download | Reuse `ResumableDownloader` (Range / If-Range, retries, mobile-data warning, free-space check) |
| UI | "Download Linux" screen: distro list → version/edition → Download → Write to USB. Same flow and progress card as Windows |
| Tests | Unit tests with mock HTTP + fixture checksum files; `:core:catalog:liveTest` extended to resolve real mirrors (run nightly) |

**Done when:** a fresh phone can download Ubuntu LTS, see a green "signature + checksum verified" state, write it,
and the stick boots on a UEFI PC.

### 2. New logo and brand (must have)

All assets are generated by `tools/brand/generate.py` from one set of paths:

- `docs/brand/anvil-icon.svg` — new master icon (smoother horn, gradient body, shaded base, bright strike face,
  spark cluster). `docs/anvil-icon.svg` is a copy for existing links.
- `ic_launcher_foreground.xml` / `ic_launcher_background.xml` — adaptive icon; artwork stays inside the 66dp safe zone
- `ic_launcher_monochrome.xml` — single-colour silhouette for Android 13+ themed icons
- `ic_notification.xml` — the same silhouette on a 24dp viewport
- `docs/brand/anvil-icon-512.png` / `-1024.png` — store and F-Droid listing icons
- `docs/brand/social-preview.png` — 1280×640 GitHub social preview (Settings → Social preview)

Still to do: refresh the marketing slides/carousel with the new icon, update the Play listing icon.

### 3. Driver folder for Windows setup (should have)

Many laptops (Intel 11th gen+ with RST/VMD) show "Install driver to show hardware … No drivers were found"
because the install media has no storage driver. Today's workaround is a BIOS change or a second USB with the driver.

- New optional toggle in the Windows write screen: **Add drivers folder**. The user picks a folder (SAF); Anvil
  copies it to `\Drivers\` on the FAT32 partition, so Browse in Setup finds it immediately.
- In-app help card on the write-complete screen: "If Setup says no drivers were found: set SATA mode to AHCI /
  disable VMD, or load your laptop's Intel RST driver from `\Drivers`".
- Full automatic driver injection stays on the roadmap for 0.6.

### 4. Stability (should have)

- "Compatibility mode" setting (16 KiB transfers) from the architecture notes, for fussy OEM kernels and cheap hubs.
- Triage beta reports on GitHub Issues; fix anything reproducible on Samsung/Xiaomi.

## Out of scope (next)

- **0.6:** stream-to-USB (write while downloading), driver injection per laptop model, NTFS + UEFI:NTFS layout,
  legacy BIOS boot.
- **0.7+:** rescue toolkit, multi-boot drive, guided install companion.

## Real-device test checklist

- [ ] Ubuntu LTS, Mint, Fedora and Debian: download, verify, write, boot on a UEFI PC
- [ ] Resume after airplane mode and after killing the app
- [ ] Bad mirror / bad checksum / bad signature shows a clear error and never writes the drive
- [ ] Windows 11 flow unchanged (regression)
- [ ] At least 2 phones (one Samsung) and 3 different USB drives
